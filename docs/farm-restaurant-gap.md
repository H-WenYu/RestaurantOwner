# 元梦之星：餐厅版功能梳理（仅餐厅，不含农场）

基于现有代码，我们把“农场”侧完全摘除，专注餐厅循环。下面是仍需补齐的要点，并注明哪些能力已经具备。

## 菜单与厨房流程
- **菜谱配置仍是硬编码**：`Dish` 通过静态列表定义，缺少表驱动/解锁条件，无法按活动或等级动态调整菜单。
- **烹饪缺原料/产量逻辑**：厨师做菜只计时和产出，没有原料消耗、单次产量、品质或失败返工，难以体现菜品差异化。
- **厨房队列与批量生产简单**：设备并发、批量制作、预制半成品尚未建模，服务高峰时缺少排产/加速手段。

## 餐厅布局与装修
- **仍不可自由布置**：`Table` 虽有 `posX/posY` 但未在 UI 中开放摆放或动线校验；没有编辑模式、区域锁或可视化网格。
- **装修缺席**：无装饰物、环境加成、清洁度/卫生状态，评分与顾客体验未与场景美化挂钩。

## 厨师出菜与服务员上菜
- **出菜链条待细化**：缺上菜口/成品区概念，菜品完成后直接结算给顾客；托盘容量、批量送餐、路径避障未实现。
- **等待/催单机制简化**：顾客等菜只靠耐心递减，没有明确的催单、补偿或超时反馈逻辑。

## 顾客、评分与经济循环
- **顾客画像薄弱**：仅有耐心/预算/偏好，缺少等位队列、预约或特殊顾客事件（VIP、节日客）。
- **评分维度单一**：评分主要来自服务速度和满意度，缺少环境、卫生、装饰等权重，也没有口碑衰减/维护玩法。
- **经济驱动可再充实**：金币/经验来源以堂食为主，任务、成就、城市扩张或多周目循环尚未成型。

## 交互与存档现状
- **已有 Swing 界面入口**：`SwingMain` 启动了包含开始/继续按钮的窗口，结合 `GameWindow` 呈现餐厅状态。【F:src/main/java/com/restaurant/SwingMain.java†L13-L147】
- **已有存档/读档**：`SaveManager` 在用户目录创建存档，保存酒店、员工、菜单等数据并可续玩。【F:src/main/java/com/restaurant/game/SaveManager.java†L12-L198】
- **界面仍需支持布局/装修编辑**：虽有 Swing UI，但尚未提供场景拖拽、桌椅摆放或装饰交互，需要在现有窗口中扩展编辑模式。

以上聚焦“餐厅版”仍需完善的核心环节，可按布局编辑 → 厨房/服务流程 → 顾客与评分循环的顺序迭代。
